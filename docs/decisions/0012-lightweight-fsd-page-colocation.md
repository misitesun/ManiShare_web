# ADR 0012：轻页面优先采用轻量 FSD 内聚

- 状态：已采纳
- 日期：2026-09-09

## 背景

注册、个人资料等单一职责页面通常包含若干视觉组件、页面交互和局部资源。若仅因为文件变长或拆出子组件，就将页面私有实现提升到 `features` 或 `widgets`，会增加跨目录跳转、公共入口和文档维护，却没有产生新的业务所有权或真实复用价值。

## 决策

- 轻页面默认在 `pages/<page>` 内聚其私有 `ui`、`model`、`lib` 与 `assets`。
- 拆分内部组件是代码组织行为，不会自动产生新的 FSD slice。
- 可独立描述的用户动作或业务流程进入 `features`，是否只有一个页面消费者不是否决条件。
- 只有跨页面复用的完整大型组合区块进入 `widgets`；小型无业务 UI 进入 `shared/ui`，稳定领域对象进入 `entities`。
- 第二个真实消费者出现时重新评估所有权，但不按调用次数机械决定层级。
- 提升或回收公共 slice 时同步消费者、根入口、README、资源、架构文档和验证，不保留无必要兼容重导出。

## 影响

- 新的轻页面不再机械创建 feature/widget；达到独立业务或跨页面复用条件后再提取。
- 该规则属于所有权判断，主要由需求清单、Skill 和 Review 执行，不使用按目录数量或引用次数扫描的 lint 代替语义判断。
