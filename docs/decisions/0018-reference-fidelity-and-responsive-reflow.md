# 0018：设计基准精确还原，其他视口独立自适应

## 背景

查漏补缺的六分类页签直接使用共享默认样式后，在1920×1080下变成18px字号和56px文案间距，偏离设计16px、36px；共享组件、语义字号与构建通过都不能证明设计还原。用户要求修正字号、字重、文字位置，并保证浏览器缩放及平板/H5预览仍能正常重排。

## 决定

- 设计基准以浏览器内容区的CSS视口为准，指定1920×1080时在100%页面缩放下验收；物理屏幕分辨率、窗口外框、设备像素比均不能替代视口尺寸。
- 基准视口逐项还原已核实的字号、字重、行高、字距、文字间距、内外边距、控件/图标尺寸、区域位置和滚动关系。文字宽度、Grid分配及绘制出现不足1 CSS px的子像素舍入时记录实际值；这不是允许2～4px偏差的容差。
- 先记录设计数值，再选择语义字号和共享组件。默认样式不能覆盖设计；同一语义角色存在不同密度时增加显式语义变体，不批量更改其他消费者。文案间距按真实文本边缘计算，不能只核对按钮的gap。
- 普通文字字体遵循用户确认的系统字体回退：Windows优先微软雅黑；Apple设备未安装微软雅黑时使用苹方；Android缺少微软雅黑时使用系统中文字体。保留sans-serif兜底，不检测UA、不增加字体网络请求。若必须保证某个设备使用指定字体，需要另行提供适用于Web的授权字体资源。此次用户明确不要求设计稿的特殊字体字形。
- 其他尺寸按内容重排：H5默认、md平板、xl桌面；每个字号角色拥有自己的下限、断点值和基准上限。字体、间距、列数及控件可以分别调整，禁止整页/根字号统一倍率、固定画布缩放或通过JS猜测设备尺寸。
- 浏览器页面缩放改变有效CSS视口时，由同一响应式CSS自然重排；不检测缩放比例再反向缩小页面抵消用户放大。触摸双指缩放的视觉视口与布局视口不同，不把它当作设备类型切换。
- 基准宽度相同但高度更小时通常保留字号和横向几何，使用自然纵向滚动；确需固定头尾的页面才由所属owner定义内部滚动。超宽屏延展容器或增加列数，文字不无限放大。
- 默认mainPage版心仍见架构约定；用户明确要求精确还原时，已核实的设计边距可以成为该页例外，写入README及影响图，不批量改无关页面。查漏补缺采用≥1920px左右254px；较窄PC16px、平板/H5既有边距和流式网格保留。

## 可执行实现

- 字号owner为 `src/fsd/app/styles/index.css`。`text-body-tight`、`text-tab-label-compact` 和 `text-action-label-compact` 分别提供14/20→16/22、14/20→16/22、16/22→18/25（字号/行高）的H5→md以上阶梯。
- `TldSegmentedTabs typography="compact" gap="compact"` 在PC输出16px字号、0.01em字距、36px文案间距；已有默认消费者保持原值。
- `TldSwitch size="compact"` 使用紧凑行高及32×20轨道，H5保留40px最小点击高度；`TldProgressBar spacing="wide"` 提供13px数值/轨道间距。业务状态和无障碍语义不随视觉变体改变。

## 验证与取舍

验收分两段，不能互相替代：首先在设计视口、100%缩放与相同侧栏状态下保存截图并读取getComputedStyle/DOM几何，逐项对照Figma；然后检查较窄/超宽PC与真实浏览器125%、150%、200%页面缩放的重排、焦点、菜单/弹窗与溢出。H5/平板可以做布局计算检查，但视觉和真机继续由用户验收。

共享视觉变体保持既有交互、受控状态和可访问名称，并在同目录测试覆盖；视觉数值由实际浏览器计算样式验收，不能用源码/class字符串断言代替。运行format、test、lint、build。字体回退、系统字形和抗锯齿差异单独记录，不能宣称跨系统像素图完全相同或已完成完整WCAG审计。
