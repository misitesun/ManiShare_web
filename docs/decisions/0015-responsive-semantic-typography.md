# 0015：跨页面文字采用响应式语义字号阶梯

## 背景

首页已有部分 mobile-first 字号，而玩家档案及其列表页混用固定 `text-sm`、`text-base`、`text-lg` 与页面局部断点。H5 抽屉和内容区变窄后，固定字号不会随信息密度调整；若通过根字号、`vw` 或整页缩放统一处理，又会让正文和辅助文字低于可读下限，并破坏按钮、行高和设计稿几何。

## 决定

- `src/app/styles/index.css` 是跨页面响应式字号的唯一 owner，通过 Tailwind `@theme inline` 暴露页面标题、区块标题、卡片标题、正文、标签、辅助文字、页签和强调操作八个语义 utility。
- 默认值服务 H5，`md` 服务平板，`xl` 服务普通 PC，≥1920px 达到设计稿字号上限；超过 1920px 不继续放大。
- 页面和共享组件按文字语义选 utility，不复制同一角色的断点数值。各角色独立确定移动端可读下限，不使用统一缩放系数。
- 排行榜数字、登录品牌首屏、极小会员徽标等与固定几何强绑定的特殊视觉继续由所属模块维护明确断点或局部有界缩放。

## 取舍

语义字号比全局根字号缩放多一步角色选择，但能保持标题层级、正文可读性、浏览器缩放和控件几何；也避免把单张 1920×1080 设计稿当作可整体缩放的固定画布。字号 token 只负责字体大小与行高，布局、点击目标和图标尺寸继续由组件 owner 负责。

## 验证

运行 `pnpm run test`、`pnpm run lint` 与 `pnpm run build`，并在 PC 的 1440×900、1920×1080 检查标题层级、按钮换行、卡片高度和溢出。平板 768×1024 与 H5 390×844 的视觉和真机兼容由用户验收。
