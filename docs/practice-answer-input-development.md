# 全模式作答输入推进

## 纠错期间回删正确字母后的推进修正（2026-10-22）

用户复现：`woman`输入`woean`并空格判错，连续删除错误`e`及前面的`o`、`w`，留下三个空位和`an`；重新输入`w`后旧逻辑直接跳回原错位2，漏过空位1。原因是待纠错列表只保留原提交错位，删除原先正确的位置没有登记。

`word-spelling-input`现在让逐位删除与原生选区清除共用`clearWordSpellingInputPositions`：纠错期间删除的实际已填位置合并进有序待重填列表，空格导航和字母覆盖沿原规则消费同一列表。上述流程重新输入后依次定位`w→o→m`；不移动其他字母，不新增提交次数，全部清空仍回到首位并清除旧错位。未提交的部分输入继续沿原“已填位＋首空位”规则；删除键的“有字先清、空位再向前定位”保持。

修正在页面私有共用字母模型生效，拼写、默写、句中练义填空与单词指法无需另加分支；句子独立分段模型、页面快捷键、IME和原生载体保持。新增实际删除顺序、空格循环、四档音标、选区删除及再次完整判词的回归用例；按用户要求未执行测试、lint、类型检查、构建或项目运行验收，只定向格式化和静态差异核对。PC／平板／H5与Electron实际输入待用户验收，未提交或推送Git。

## 当前输入分工补充（2026-10-22）

中译英抄写模式由句子局部`copy`选项控制未录入位置的灰色词形提示，默写隐藏；提示只展示，不计入原生段值、判题数组或Undo历史，切换模式保留作答。输入实际文字固定绿色，已提交的错误文字为红色；只限定`SentenceAnswerInput`，不改变单词输入与全局自定义字色。

句子中译英提交后全选首个错误段；切换或归焦到其他错误段也全选。首次字符输入替换整段，Backspace／Delete及原生删除清空当前错段并恢复pending，随后按普通编辑处理；其他段与提交次数不变。选区使用UTF-16派生，重复提交／首错索引不变时仍同步，保留原生输入和IME／229门控、句子Undo／Redo。此规则只在`SentenceAnswerInput`生效，不改变单词输入。

句子中译英按段保存、允许跳过空段，当前提交以每段非空为门槛，现由独立`SentenceAnswerInput`／`sentence-answer-input`负责，成为下方2026-10-21统一字母推进规则的显式例外。每段不限答案字数，原始数组作为判题输入；未填齐时Enter／按钮只导航，末段回到首个空段；全部段非空后Enter／按钮可提交，首次作答空格仅在末段提交；纠错中当前段已编辑、后续段全已判对且所有段非空时可原地空格提交，其他情况只跳下一段；左右按段移动。空段／错词／少字／多字都保留原文与位置，判错定位首错，编辑只清对应反馈。句子模型使用自己的100次编辑历史，原生input传输当前段，不把全部段串成一个字母缓冲。

`PracticeInputBridge`是共同的原生载体，统一真实input标记、固定输入属性与隐藏样式；单词的受控字母逻辑与句子的分段逻辑分别维护，IME提交和去重仍在各自组件内。句子通过既有控制器接入唯一页面快捷键监听；上下答案和Shift切题先由页面消费，普通左右交给句子跳段，其他消费者继续阻止普通定位。源代码和回归断言只在句子工作区实现，按用户要求未执行测试、构建或运行验收。

2026-10-21，用户确认将单词拼写的受控输入逻辑推进到所有模式。适用现有练习页的真实文字作答；笔记、草稿、报错表单、词块按钮和媒体滑杆仍由各自所有者处理。本轮没有新增设计节点、接口、路由、依赖、主题或存储。

## 影响图与归属

- 所有者保持 `pages/practice`。`PracticeInputBridge`是共用原生载体；`PracticeAnswerInput`／`word-spelling-input`与`SentenceAnswerInput`／`sentence-answer-input`分别维护字母和句子词段的状态，保持页面内部实现，不向其他FSD slice开放深层导入。
- `WordAnswerCard` → `WordSpellingInput`（历史名称兼容入口）→ `PracticeAnswerInput`：单词拼写、单词默写，保留原有字母／音节下划线、题面、正确态、口语入口和统计。
- `WordMeaningExercise` → `PracticeAnswerInput presentation="inline"`：打词填空直接使用同一默认字母槽、4px逐位底线及latin整词回退，不再经`PracticeWordSlotsInput.renderSlots`替换渲染。行内变体只处理句子字号、字卡留白与重排，原solid／dashed设置继续生效，输入与正确态共用可自然撑开的Grid测宽；拼写／默写默认布局和事件模型不变。回归用例已补但未执行，PC几何、真实键盘、缩放及平板／H5效果仍待验收，详见[句中练义修正](practice-word-meaning-development.md#输入框渲染对齐修正2026-10-21)。
- `WordTypingExercise` → `PracticeAnswerInput presentation="typing"`：单词指法直接使用默认字母槽，变体只去掉字卡留白、继承指法字号并允许窄屏重排。抄写模糊未填提示、默写隐藏，键盘／手型读取同一逻辑光标；题面不另注册键盘或定位规则。详见[单词指法记录](practice-word-typing-development.md)，本轮未运行测试或项目验收。
- `SentenceExercise`／`SentenceTypingExercise` → `SentenceAnswerInput` → `PracticeInputBridge`：句子中译英和指法共用独立词段输入，提交通过`onSentenceSubmit`携带段数组。指法通过可选`inputRef`复用同一个原生桥，`onEditingChange`只投影当前段ID、目标、原文和Unicode光标供现有只读键盘使用；错误段待整段替换时提示位置为0，跳段重置键盘瞬时反馈。不创建第二套输入、全局监听或整句长度推算，原中译英不传这些可选参数时行为不变。
- `PracticeContent` → `PracticeWordSlotsInput` → `PracticeAnswerInput`：其他单词输入、音频／视频／看图中译英、猜词和其他指法输入。整词外观仍由适配视图渲染，已删除原生选区定位、点击补空格及 `execCommand` 路径。
- `PracticePage` → `PracticeContent.onAnswerController/onAnswerSubmit`：所有文字输入注册同一控制器。主动作交给 `submit`；内容区空格交给 `space`；输入聚焦时空格由输入器消费，避免页面重复执行。
- 快捷键事件顺序：`usePracticeCommands`仅对作答输入使用捕获阶段监听，先解析现有绑定并阻止原生默认行为；已命中的事件由输入器让行，未命中的普通左右键仍由输入器屏蔽。作答输入不再进入页面冒泡监听，避免重复派发；其他控件／弹窗保持原冒泡顺序，卸载时成对清理捕获监听。修复“输入聚焦后Shift＋左右被局部stopPropagation吞掉”的回归，保留长按去重和IME门控。
- 焦点恢复：输入控制器的`focus`只聚焦当前可编辑输入器，保留字母、待修改位与逻辑位置，不聚焦disabled／inert内容；控制器在布局Effect随DOM提交注册，保证父级翻转完成回调可立即使用。拼写的`WordSpellingQuestionFlip.onReady`在当前卡牌可见后归焦，覆盖首次聚焦早于翻转结束的缺口；旧卡仍禁用且不注册页面控制器。
- 局部设置（抄写／翻译／切读／音标等）提交后，`PracticePage`通过`practice-answer-focus`合并下一帧归焦，等待选择器先完成自己的触发按钮还焦；全局设置在`TldDialog.onAfterClose`后请求。所有真实作答模式共用此入口，弹窗／暂停／完成／只读时不抢焦点，卸载取消待执行帧。初次自动聚焦的保护条件保持，不在任意渲染或blur时强行拉回焦点。
- 选项浮层保持打开：`PracticeToolbarOptions`允许焦点返回同一练习宿主的作答input，修改设置不会因blur关闭，外点、再次触发和Esc仍关闭；Esc从作答输入走冒泡，先交由局部浮层／解析处理，避免误触页面暂停。`PracticeToolbarOptions`与`TldSelect`共用`shared/lib/popover-trigger`：PC的xl布局且hover／fine鼠标悬停展开，触控／平板／H5点击，Hover不抢焦点。TldSelect单选后仍关闭，复选／开关选项浮层不关闭；Portal边界、150ms离开取消与键盘焦点保护共用。
- `TypingKeyboard`继续只读。提示跟随模型的实际编辑位；反馈读取已提交输入值，避免覆盖字母时读到瞬时原生缓冲。空格负责导航；指法保留标点录入，其余文字模式仍按题目提供静态标点。

## 单词与其他原字母消费者规则

1. 无内容时逻辑位置为0。点击任意字母、整词、输入空白或音标只聚焦／播放反馈，不改变作答位置；禁止拖选定位。
2. 纯左右键及未被页面命令消费的修饰左右键都阻止原生定位；Home／End同样不能定位。已明确配置的切题快捷键仍由页面先执行。输入法组合及229期间不接管编辑。
3. 部分输入时，允许位置为“所有已填位＋首个空位”，按顺序循环。目标 `apple`、输入 `app`，从当前首空位按空格依次是 `a→p→p→l→a`，不能跳到 `e`。删除留空后仍按实际位置集合派生，不按输入总长度猜位置。字母覆盖当前位后自动推进，不插入、不挤动其他字母。
4. 填满后空格或Enter才校验。Enter／提交按钮在未填满或仍有待修改位时保持原位置，不提前判错、不增加提交次数。
5. 提交错误时定位首错。空格只循环待修改位；直接覆盖或先Backspace清空再填入都自动跳下一待修改位。删除不移除该位的纠错身份；输入任意字母代表该位已修改，是否正确等全部修改后再次校验。
6. Backspace／Delete清当前已有字母并留在该位；当前为空时仅向前寻找已填字母，不循环到后面的未填位置。全部清空回到0并清除旧错位。
7. 全文选择可用于复制／剪切／粘贴和整体替换，不恢复任意位置定位。Undo／Redo使用最多100次模式内历史，不承诺等同OS原生历史；会话提交统计不随编辑撤销回退。复制经过 `shared/lib/clipboard`输出含题目静态分隔符的作答值；剪贴板失败或等待期间作答已变更时不删除原内容。

## 数据与兼容边界

原生input只作为键盘、软键盘、剪贴板和组合文本的传输桥；其缓冲由已填字符组成，不用于推导逻辑位置或提交全文。提交与onChange通过题目模板恢复静态空白和标点。单词拼写／默写维持ASCII字母契约，其余文字模式接受Unicode文字与数字；指法另外保留非空白标点／符号作为待输入位。词间空白由题目提供，位置按码点计数，原生选择范围按UTF-16处理。固定作答容量由题目确定；粘贴不会循环覆盖前面的字符或新增输入槽。切题／重练重建状态；提示与可见分组不拥有第二套光标。

所有文字模式使用给定目标答案做本地精确匹配演示，遵守忽略大小写设置，不推断同义词、等价译法或正式评分。`submit-answer`只更新本地输入／题态；拼写／默写及单词指法用`submit-spelling`更新本轮提交统计。句子指法通过`submit-sentence-typing`校验完整原始段数组并更新同一统计，导航、未填齐、揭晓、答对后重复提交不计次；切题保留、重练清零，不新增奖励规则。句子指法的空格／左右跳段、静态标点、错段全选重填与纠错快捷提交沿中译英契约；其他指法继续原字母推进规则。词块、自查、阅读、口语评测及正式接口边界保持各自流程。
