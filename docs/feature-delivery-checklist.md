# 新页面与新能力需求就绪清单

本清单用于把已经确认的产品需求转换为可实施边界。它不是要求所有任务填写长文档；简单静态页面可以将不适用项标为 `N/A`。普通任务只在未决项会实质改变范围、FSD 归属、公共契约或验收结果时暂停；设计稿驱动的实现任务则无论是否还有歧义，都必须在展示基于仓库现状的开发清单后暂停，等待用户明确确认。

## 1. 目标与范围

- 提供设计稿并要求实现时，是否已读取设计，并核对现有路由、FSD 所有者、模块 README、公共入口、组件、状态和测试；是否在编码前向用户展示[五项简版实施方案](./ai-collaboration.md#设计稿驱动任务的编码前方案)、明确请求确认，并在收到确认前保持只读；

- 页面或能力解决哪个用户问题，明确不包含什么；
- 页面语义路由、路径参数和查询状态是否确认；
- 是新建、替换还是扩展现有页面/能力；
- 是否有设计稿、接口文档、文案或既有行为作为事实来源。

## 2. FSD 归属与公共边界

- 页面私有 UI、Hook、状态和资源是否留在 `pages/<page>`，而不是仅因拆文件建立公共 slice；
- 跨页面复用的完整大型区块是否属于 `widgets`；
- 可独立描述、拥有业务状态/API/测试边界的用户动作是否属于 `features`；
- 稳定业务对象是否属于 `entities`；
- 无业务语义的能力是否已有 `shared` 唯一入口；
- 第二个真实消费者是否真的改变了所有权，而不只是触发一次重新判断；
- 新增公共 slice 是否需要根 `index.ts` 和模块 `README.md`。

## 3. 数据与状态

- API 请求、参数、响应和错误契约是否确认；
- 是否按[接口能力边界](./api-capability-boundaries.md)确认当前接口足够提供哪些数据、哪些字段缺失，以及默认图/空态和反馈文档；复用组件是否引入自动请求、预加载或状态写入；额外补齐请求是否有明确需求与已有授权；
- 外部输入是否以 `unknown` 进入校验和 DTO 转换；
- idle、loading、success、empty、error、无权限和重试状态中哪些真实存在；
- 是否涉及本地持久化、URL 可恢复状态、时间、上传下载或剪贴板；
- 领域数值是否明确单位、范围、精度、舍入和非法输入语义。

## 4. 交互与基础无障碍

- 主操作、次操作、禁用条件、取消和失败反馈是否确认；
- 交互是否使用原生语义元素并可由键盘完成；
- 所有真实可操作元素是否显式使用 `cursor-pointer`，禁用或纯展示内容是否避免使用 pointer 光标；
- 是否逐项检查清空、关闭、密码显隐、下拉、折叠、分页、可点击卡片及选择控件，包括输入非空或展开后才出现的内部操作与浏览器原生子控件；输入区域是否保持文本光标，禁用/只读态是否覆盖手型；PC 是否悬停实际点击位置而非只检查容器；
- 图标按钮、菜单、抽屉和表单是否有名称、状态、焦点与错误信息；
- 动画是否需要 reduced-motion 下的直接结果。

## 5. 响应式、主题与文案

- 390×844、768×1024、1440×900 下的布局与信息优先级是否明确（这是实现目标，不代表三个视口均由 Codex 做视觉验收）；
- 是否复用同一语义 DOM，通过默认、`md:`、`xl:` 重排；
- App Shell 内常规列表/管理页是否采用[mainPage 版心约定](./architecture.md#mainpage-版心与列表适配)，取消 PC 页面级固定最大宽度，在相同视口/侧栏状态下核对同类页面的精确边距与内容边界，并按内容确定自适应列数；特殊布局例外是否有用户确认并已记录；
- 长文本、空数据、窄屏溢出、Safe Area 和局部滚动是否有验收方式；
- dark/light 是否只消费现有语义 token，是否确有新增 token 的跨组件消费者；
- 当前阶段的用户可见文本是否已提供明确中文；默认可直接使用中文字面量，不要添加占位英文或强制新增 i18n key。只有需求明确重新开启多语言时，才检查相关语言资源是否同步。

## 6. Web、设备与 Electron

- Web、H5、平板、Electron 是否保持相同行为；
- 是否涉及媒体、输入、文件、权限、窗口、后台恢复或系统能力；
- 若存在运行时差异，是否已读取兼容性索引并定义 Web 回退、失败语义与人工复测环境；
- renderer 是否仍不直接依赖 Node/Electron API。

## 7. 验收与交付

- 哪些解析、状态转换、公式、共享行为或缺陷路径必须有单元测试；
- PC 视觉验收尺寸是否明确：优先任务/设计稿指定尺寸，未指定时使用 1440×900；
- 平板/H5 的视觉、横竖屏和真机兼容是否在交接中明确列为待用户验收，且没有被 Codex 声称为已通过；
- 除多端视觉外，哪些主题、浏览器或 Electron 运行时行为仍需要人工复测；语言切换仅在本次任务明确涉及翻译时进入验收。
- 是否改变路由、公共入口、语言 key、存储键、主题 token、环境、依赖、CI 或 Electron bridge；
- 受影响的模块 README、全局文档、ADR、兼容性契约或 todo 是否已列入同一任务；
- 源代码、脚本和配置是否已通过 `pnpm run format` 统一为 4 空格缩进且不包含 Tab；
- 完成后运行 `pnpm run test && pnpm run lint && pnpm run build`，涉及 Electron 边界时再运行 `pnpm run desktop:build`。

## Skill 选择

- 业务页面、业务能力或缺陷：`learning-web-feature-delivery`；
- 路由或公共契约同时变化：叠加 `learning-web-cross-cutting-change`，由它负责影响图；
- TSX 运行逻辑、Hook、状态、Effect、列表、加载或组件重构：再叠加 `learning-web-react-engineering`；
- 已有实现完成后：`learning-web-change-review` 只读审查，不直接修复。
