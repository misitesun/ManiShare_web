# 接口能力边界与缺失数据处理

适用于真实业务接口接入、数据加载变更以及带有请求行为的组件或 Hook 复用。当前任务及会话中已明确的需求与授权是判断依据；已有授权无需重复确认。

## 核心约束

- 前端应以当前业务接口的返回数据实现功能，不得为补齐缺失字段，擅自增加详情查询、逐条请求、跨接口拼接或预加载。
- 复用组件前，必须检查其隐含副作用，包括自动请求、数据补全、预加载和状态写入；不能因复用 UI 而引入当前场景不需要的业务行为。必要时在原所有者内分离展示与加载职责。
- 接口缺少图片、例句等数据时，优先使用已有默认图或空态，保留必要布局。不要擅自隐藏整个功能区域，也不要伪造数据。默认图和空态仅用于展示，不得写成已返回的业务数据；必需字段缺失仍按接口错误契约处理。
- 列表展示和练习所需的数据，应由后端在对应业务接口中完整返回。缺失字段、影响范围和后端待确认事项应记录到反馈文档。
- 只有需求明确要求且已获授权时，才通过额外接口补齐数据；不能仅因技术上可行，就自行实现复杂的补偿方案。已确认的分页、详情查看或用户操作请求按原需求执行；并行化、缓存和组件复用都不构成扩大请求范围的授权。
- 验证不仅检查页面能否正常展示，还要检查请求次数、请求来源和是否存在不必要的数据补全。

## 缺失数据反馈

优先更新任务已有反馈文档；没有时，首次发现真实缺项再创建 `docs/api-feedback/<业务模块>.md`，交接时链接到该文件。不要提前创建空反馈记录或把猜测写成后端事实。

每条记录包含：对应页面/操作、接口方法与路径、响应中实际缺失的字段、脱敏证据、影响范围、当前默认图/空态/错误处理、后端待确认事项及处理状态。额外请求已获授权时，记录授权来源、端点、触发条件和预期次数。不要记录令牌、真实账户或敏感响应。

## 验证证据

- 核对首次进入、重渲染、列表追加、组件复用和明确用户操作下的请求来源与次数；列表有 N 条数据不应无授权地额外产生 N 次详情查询。
- 使用受控请求替身验证缺失数据不会触发额外请求，以及默认图、空态或契约错误的处理；已有条件允许时，补充浏览器 Network 的实际结果。无法联调时说明验证范围，不宣称完成真实接口验收。
- 静态 UI 任务已明确使用的 mock 数据可继续使用，但不得在真实接口缺项时混入 mock 冒充后端数据。
- 是否必要或已获授权属于语义审查，不由关键词 lint 自动判定。Skill 路由、行为测试和请求证据共同执行本规范。
